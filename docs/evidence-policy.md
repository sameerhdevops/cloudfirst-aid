# Evidence Provenance, Privacy, & Redaction Policy

CloudFirst Aid treats diagnostic evidence as first-class engineering artifacts. Every troubleshooting conclusion in this project is anchored to concrete data items with verifiable origin and integrity constraints.

---

## 1. The Three Evidence Categories

Every evidence record processed by CloudFirst Aid belongs to one of three strictly tracked provenance categories:

### Category A: Simulated Evidence (`provenance = "simulated"`)
- **Definition:** Synthetic diagnostic output shipped in version-controlled fixture files (`tests/fixtures/evidence_*.json`).
- **Purpose:** Reproduces complex cloud failures (e.g. ALB target health timeouts, S3 explicit deny bucket policies, Linux inode exhaustion) without requiring live cloud infrastructure or destructive local actions.
- **Reporting Invariant:** All simulated evidence is visibly branded with a `[SIMULATED]` provenance tag in incident reports and terminal summaries. It is never presented as actual production telemetry.

### Category B: Locally Collected Evidence (`provenance = "local"`)
- **Definition:** Read-only system snapshots generated by running safe diagnostic scripts (e.g. `scripts/collect_linux_diagnostics.sh`) on the engineer's active operating system.
- **Purpose:** Enables learners to inspect and compare their own machine's filesystem usage, process table, and listening sockets.
- **Safety Guarantee:** Script execution is strictly non-destructive. It never modifies services, alters partitions, or executes destructive file removals.

### Category C: Live AWS Evidence (`provenance = "live_aws"`)
- **Definition:** Data retrieved directly from the Amazon Web Services API via read-only SDK calls (`Describe*`, `Get*`).
- **Purpose:** Validates actual EC2 instance state and attached security group ingress rules when an engineer chooses to inspect a live sandbox environment.
- **Safety Guarantee:** Purely opt-in; never executed during installation, unit tests, or offline triage.

## 2. Privacy & Secret Sanitization Engine

Before any evidence string is stored in a report or displayed in CLI output, it passes through the automated redaction engine (`src/cloudfirst_aid/evidence.py:redact_sensitive_fields`).

### Automated Redaction Patterns:
1. **AWS Access Key IDs:** Replaces standard 20-character AWS access key identifiers starting with `AKIA` (permanent) and `ASIA` (temporary STS sessions) with masked placeholders:
   ```
   AKIAIOSFODNN7EXAMPLE  -->  AKIA****************
   ASIAIOSFODNN7EXAMPLE  -->  ASIA****************
   ```
2. **AWS Secret Access Keys:** Replaces 40-character base64-encoded credential strings with `[REDACTED]`, while preserving 40-character Git commit hexadecimal hashes.
3. **AWS Account Numbers:** Masks 12-digit AWS account IDs:
   ```
   123456789012  -->  ************
   ```
4. **Private Key Blocks:** Redacts entire PEM, RSA, and OpenSSH private key blocks (`-----BEGIN ... PRIVATE KEY-----` to `-----END ... PRIVATE KEY-----`).
5. **Bearer & Authorization Tokens:** Masks HTTP bearer tokens and sensitive password assignment strings.

### Scope & Inherent Limitations:
Pattern-based regex redaction is a defense-in-depth safety measure applied at terminal-display and report-generation boundaries. It cannot guarantee detection of every possible arbitrary secret format, custom token structure, or obfuscated credential.
- **Operator Responsibility:** Never input production credentials, customer secrets, or live private keys into evidence fixtures.
- **Safe Fixtures:** Always use synthetic dummy identifiers (e.g., standard AWS documentation examples such as `AKIAIOSFODNN7EXAMPLE`) when constructing test evidence.
- Redaction acts as an automated safety net to mitigate accidental disclosure, not as an absolute guarantee of total data sanitization.

---

## 3. Storage and Repository Safety
- All private incident reports generated during local experimentation are excluded by default via `.gitignore` (`reports/private/`).
- The repository only contains clean, sanitized public example reports in `examples/reports/`.
- No credentials, tokens, cookies, or real host IP ranges are committed to version control.
